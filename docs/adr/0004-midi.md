# ADR 0004 — MIDI pipeline

Status: accepted

MIDI is layered as source, loader, parser, normalized model, transport,
scheduler, and audio backend. Web Audio is the clock; position is exposed via a
small external store. Raw data is cached by source hash, parsed data stays in
memory, and render cache is bounded (current default: 128 MiB).

The current domain slice includes a bounded SMF parser (program, percussion,
tempo, running-status, and note events), hash-verifying loader, transport state
machine, and playlist CRUD/mode state. The web transport now prefers a local
FluidSynth WASM worker with packaged TimGM and optional GeneralUser-GS and
renders a reusable AudioBuffer keyed by source hash/tempo/transpose/instrument/
sample rate. Previous and next tracks use the same key for background preload.
A deliberately small Web Audio oscillator backend remains available when
a browser blocks workers or WASM; the shell labels that backend so a failed
render is never mistaken for a canonical soundfont render. The bounded render
cache and canonical-vs-rewrite performance benchmark remain release gates.

## Implementation review — 2026-10-07

TimGM6mb is the packaged default; GeneralUser is an optional verified download.
The current `MidiRenderCache` default is **128 MiB**, replacing the earlier
96 MB implementation recorded in earlier receipts. One key owns PCM or AudioBuffer, not both;
presence checks avoid copies. Opening the player does not render audio until
Play, and neighboring synthesis starts only with active playback.

Transport/instrument/key/transpose remain visible in the compact expanded dock;
utility controls use one menu. The single half-circle edge tab preserves session
and preferences, supports pointer/touch/keyboard movement and distinguishes drag
from tap. See [MIDI matrix](../discovery/midi-capability-matrix.md).
