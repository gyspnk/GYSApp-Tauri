# Clean-room provenance

| Role                               | Repository           | Immutable reference | Access rule                            |
| ---------------------------------- | -------------------- | ------------------- | -------------------------------------- |
| Functional source of truth         | `ThenGB/GYSAPP-Fork` | `4f0d39b`           | Read-only discovery                    |
| Canonical music/chord/asset source | `gyspnk/gyschordweb` | `cbc7d386`          | Read-only discovery and generated lock |

The new repository has no copied history and does not use `ThenGB/gysapp` as a
seed. Derived snapshots must be generated by `scripts/generate-music-lock.mjs`
with `GYSCHORDWEB_SNAPSHOT` pointing at a read-only checkout. A reviewed pull
request is required for any lock update. `generate-chord-manifest.mjs` derives
the 140-entry BFF manifest from that lock, while `generate-hymn-catalog.mjs`
and `generate-bible-reader-pack.py` build the user-facing projections. CI runs
`verify:generated` to detect source-commit, count, byte, or SHA-256 drift.

## Discovery evidence

- `GYSAPP-Fork`: Flutter 3.44.1, all 341 tests passed during the initial audit.
- `gyschordweb`: 533 PDF entries and 140 chord entries validate; the Node test
  command currently discovers zero automated tests.
- Initial MIDI observations (not a release gate until repeated): GeneralUser
  soundfont ~29.2 MB, viewer-ready ~2.15 s, first position ~1.14 s, seek
  ~0.42 s, heap ~167 MB. Duplicate MIDI fetches were observed in the canonical
  page. The official baseline will be repeated as cold/warm median and p95 on
  the same fixture and machine.

The PDF detail path now consumes the clean-room generated
`fork-hymnal-manifest.json` (KR master PDF page ranges) derived from the
`GYSAPP-Fork` index. On the web it fetches the matching KR master PDF from the
same immutable `GYSAPP-Fork` commit first, caches it atomically, and validates
the PDF signature. It then falls back to the signed `GYSApp-Data` KR package
with the same checksum/decode rules as the functional source, and finally to
the immutable `gyschordweb` per-song PDF when the package is unavailable. The
viewer remains local PDF.js with page, layout, zoom, and download controls.
