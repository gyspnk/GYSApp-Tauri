# Compact Sauh and Bible archive audit — 9 October 2026

Sauh loading uses the shared animated progress bar without a logo. Other loaders
retain their logos. The card follows intrinsic content height, including enlarged
fonts; responsive bounds checks cover 320/390/768/1440 px at 100/150% font size.

## Proven size candidate

The bundled SQLite database contained an unused `bible_old` archive and its
unique index. Runtime queries in `apps/web/src/bible-sql-runtime.ts` and the reader
generator use the active `bible` table. A repository search found no consumer of
`bible_old`. This is an archive omission, not lossless preservation of that obsolete
table. The pinned upstream source remains available in project history.

The opt-in `--drop-legacy` compactor verifies all remaining schemas, rows, row IDs,
user_version, application_id and integrity before replacing the file. Removing the
archive requires an active `bible` table. Default compaction retains all tables.
The canonical browser reader JSON regenerated byte-identically: 66 books,
31,172 verses, 2,305 pericopes and 1,912 cross-reference groups. Offline reading,
search, alternate-version SQLite support, reader fallback and reference behavior
remain unchanged. No new runtime decoder or first-launch conversion was added.

## Published native measurements

Release [`v0.1.0-preview.20261009.1`](https://github.com/gyspnk/GYSApp-Tauri/releases/tag/v0.1.0-preview.20261009.1)
packages source `394b2e336ff2ca404984134298c6c056f498ed98`.
Both downloaded public artifacts match their SHA256 manifests, source commits,
and provenance byte counts. APK signature, ZIP alignment, ARM64 compressed JNI,
and 16 KiB ELF load alignment were verified again locally.

CI passed 742 browser cases with no retries and three BFF-dependent skips. The
new integration test projects the actual packaged SQLite with SQL.js and compares
all books, verses, pericopes and numeric cross-references with the canonical reader.
Five compactor tests and eight loading bounds/font-scale cases passed locally.
Initial browser JavaScript remains within the 180 KiB budget at 178.9 KiB gzip.
The 30-navigation local browser audit measured median 373.3 ms / p95 394.2 ms,
with no repeated application module downloads. These measurements do not imply
remote provider latency or Android cold-launch timings.

The packaged APK passed Android 17 emulator checks for More/cold restart, idle
audio focus, font_scale 2.0, cutouts in portrait/landscape and gesture/three-button
navigation. This is a preview APK signed with the debug identity; Windows remains
unsigned, with no Windows-device runtime test performed. Full hashes and verified
active row counts are in the companion JSON audit.
All ten doctrine PDFs, the complete TimGM6mb soundfont, Bible SQL and JSON fallback
remain bundled. A compact-tuple reader projection saved only 126,059 Brotli bytes;
it was not applied because the archive candidate gives a larger saving with no
runtime format migration. Earlier APK recompression and larger NSIS dictionaries
were rejected because they produced larger or equal artifacts.

Reproduce: `python scripts/compact-bible-database.py --drop-legacy --write`,
then `python scripts/generate-bible-reader-pack.py` and
`pnpm generate:offline-manifest`. The active content comparison is performed by
the compactor, not inferred from file size. Unit tests cover opt-in behavior,
read-only audit, missing active table rejection, row-ID changes and idempotence.
